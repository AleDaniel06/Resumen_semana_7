// NIVEL 01 · FUNDAMENTO

¿QUÉ ES UNA
TABLA?

📋 DEFINICIÓN

Una tabla es un objeto de la base de datos que se usa como almacenamiento de datos. Tiene formato fila-columna similar a las tablas o listas de Microsoft Excel.

📌 FILAS (Registros)

Cada fila es un registro único. No existe una fila igual a otra en la misma tabla.

📌 COLUMNAS (Campos)

Cada columna almacena valores de propiedades específicas del registro. Se debe definir el tipo de dato antes de crear la tabla.

📌 TIPO DE DATO

Define el tipo de información (cadena, número o fecha) que la columna almacena. Cada columna debe contener solo un tipo.

🗂️ EJEMPLO: TABLA EMPLEADO

Cada fila = un empleado único. Columnas posibles:

apellido_paterno
cadena
fecha_nacimiento
fecha
estado_civil
cadena
numero_hijos
numérico

⌨️ SINTAXIS CREATE TABLE

Sintaxis básica para crear una tabla:

T-SQL · CREATE TABLE
CREATE TABLE nombre_tabla (
nombre_columna1 tipo_dato1 [NULL|NOT NULL] ,
nombre_columna2 tipo_dato2 [NULL|NOT NULL] ,
nombre_columna3 tipo_dato3 [NULL|NOT NULL] ,
…
)
NULL / NOT NULL: establece si el dato es obligatorio (NOT NULL) u opcional (NULL). Si no se especifica, el valor predeterminado depende de la opción de configuración ANSI null default de la BD.

📊 EJEMPLO TABLA TIENDA

T-SQL · TABLA TIENDA
USE QhatuPERU
GO

CodTienda int NOT NULL ,
Direccion varchar(60) NULL ,
Distrito varchar(20) NULL ,
Telefono varchar(15) NULL ,
Fax varchar(15) NULL )

TIPOS DE DATOS
EN SQL SERVER 2022

SQL Server organiza sus tipos de datos en 7 categorías. Antes de crear una tabla es fundamental conocerlos para asignar el tipo correcto a cada columna.

🔢 2.1 NUMÉRICOS EXACTOS

Permiten especificar exactamente la escala y precisión. Se usan en aplicaciones financieras donde se requiere consistencia (ej: siempre 2 decimales).

Tipo de dato Descripción
bitEntero. Solo puede tomar el valor 1, 0 o NULL.
tinyintEntero de 1 byte. Valores de 0 a 255.
smallintEntero de 2 bytes. Valores de −2¹⁵ (−32,768) a 2¹⁵−1 (32,767).
intEntero de 4 bytes. Valores de −2³¹ a 2³¹−1 (±2,147,483,647).
bigintEntero de 8 bytes. Valores de −2⁶³ a 2⁶³−1 (±9,223,372,036,854,775,807).
decimal(p,s)p = precisión (1–38, default 18). s = escala (0 hasta p).
numeric(p,s)Equivalente a decimal. Mismo rango y comportamiento.
smallmoneyValor monetario de 4 bytes. De −214,748.3648 a 214,748.3647.
moneyValor monetario de 8 bytes. De −922,337,203,685,477.5808 a 922,337,203,685,477.5807.

📐 2.2 NUMÉRICOS APROXIMADOS

Almacenan datos sin precisión exacta. Usados en aplicaciones científicas con gran cantidad de decimales.

TipoDescripción
float(n)Si n=1–24: 4 bytes, 7 dígitos. Si n=25–53: 8 bytes, 15 dígitos. Default n=53.
real / float(24)Numérico de 4 bytes. Valores de −3.40E+38 a 3.40E+38.

📅 2.3 FECHA Y HORA

Pueden almacenarse como datetime o smalldatetime. Desde SQL Server 2008 también existen tipos separados.

TipoDescripción
datetime01/01/1753 – 31/12/9999, intervalo 00:00:00 a 23:59:59.997. 8 bytes.
smalldatetime01/01/1900 – 06/06/2079, intervalo 00:00:00 a 23:59:59. 4 bytes.
dateFecha del 01/01/0001 al 31/12/9999. 3 bytes.
datetime2(p)01/01/0001 al 31/12/9999, precisión de 100ns. p=0–7 dígitos.
time(p)00:00:00.0000000 a 23:59:59.9999999. p=0–7 dígitos.
datetimeoffset(p)Fecha y hora con reconocimiento de zona horaria.

🔤 2.4 CADENAS DE CARACTERES

Para almacenar cadenas de caracteres NO Unicode.

TipoDescripción
char(n) / character(n)Longitud fija. n puede ser 1 a 8000 bytes.
varchar(n|max)Longitud variable. n=1–8000. max indica hasta 2³¹−1 bytes.
text *Longitud variable hasta 2³¹−1 caracteres. *Reemplazar por varchar(max).

🌐 2.5 CADENAS UNICODE

TipoDescripción
nchar(n)UNICODE longitud fija. 1–4000 caracteres. Almacenamiento = 2n bytes.
nvarchar(n|max)UNICODE longitud variable. 1–4000 caracteres. max = 2³¹−1.
ntext *UNICODE variable hasta 2³¹−1. *Usar nvarchar(max).

💾 2.6 CADENAS BINARIAS

TipoDescripción
binary(n)Binario longitud fija. n = 1–8000 bytes.
varbinary(n|max)Binario longitud variable. n=1–8000. max = 2³¹−1.
image *Binario variable 0 a 2³¹−1. *Usar varbinary(max).

🔧 ALTER TABLE — MODIFICAR UNA TABLA

Permite modificar la definición de una tabla existente. Opciones principales:

T-SQL · ALTER TABLE
ALTER TABLE nombre_tabla
ADD nombre_columna propiedades_columna
| DROP COLUMN nombre_columna
| ALTER COLUMN nombre_columna
nuevas_propiedades_columna
| ADD CONSTRAINT nombre_restriccion
PRIMARY KEY… | UNIQUE… |
FOREIGN KEY… | DEFAULT… |
CHECK…
| DROP CONSTRAINT nombre_restriccion
✦ ADD nombre_columna: crea una nueva columna en la tabla.
✦ DROP COLUMN: elimina una columna existente.
✦ ALTER COLUMN: cambia las propiedades de una columna.
✦ ADD CONSTRAINT: añade una restricción (PK, FK, UNIQUE, DEFAULT, CHECK).
✦ DROP CONSTRAINT: elimina una restricción existente.

📌 PROPIEDAD IDENTITY

Permite definir una columna numérica entera cuyo valor es autogenerado secuencialmente a medida que se insertan filas. Útil para claves primarias numéricas.

T-SQL · IDENTITY — TABLA LINEA
USE QhatuPERU
GO
CREATE TABLE LINEA (
CodLinea int IDENTITY(1,1) PRIMARY KEY,
NomLinea varchar(20) NOT NULL,
Descripcion varchar(40) NULL )
GO
IDENTITY(semilla, incremento): semilla = primer valor, incremento = cuánto aumenta por cada inserción.

🔍 sp_help — VER DEFINICIÓN DE TABLA

El procedimiento de sistema sp_help genera un reporte que muestra la definición de un objeto de la BD. Lo puede ejecutar cualquier usuario.

T-SQL · sp_help
-- Ver definición de una tabla:
sp_help nombre_objeto_basedatos
-- Ejemplo real:
sp_help TIENDA
GO

El reporte muestra: propiedades principales de la tabla, definición de cada columna, restricciones e índices.

➕ AGREGAR COLUMNA CON ALTER TABLE

T-SQL · ADD COLUMN
-- Añadir columna NULL (siempre funciona):
ALTER TABLE TablaPrueba
ADD campo4 MONEY NULL
GO
-- Añadir columna NOT NULL a tabla con datos:
-- Paso 1: agregar como NULL
ALTER TABLE TablaPrueba
ADD campo6 DECIMAL(12,3) NULL
GO
-- Paso 2: actualizar valores existentes
UPDATE TablaPrueba SET campo6 = 123.456
WHERE campo1 = 1
-- Paso 3: redefinir como NOT NULL
ALTER TABLE TablaPrueba
ALTER COLUMN campo6 DECIMAL(12,3) NOT NULL
GO
Nota: ALTER TABLE solo permite añadir columnas NOT NULL si no hay datos existentes, o si la columna tiene DEFAULT, o si es columna IDENTITY.

🗑️ DROP TABLE — ELIMINAR TABLA

T-SQL · DROP TABLE
DROP TABLE nombre_tabla
-- Ejemplo:
DROP TABLE ORDEN_DETALLE
GO
⚠️ Importante: Si la tabla es referenciada por una FK, primero debe eliminarse la tabla que contiene la clave foránea, luego la tabla referenciada.

// NIVEL 04 · INTEGRIDAD

INTEGRIDAD
DE DATOS

La integridad de datos es el mecanismo para garantizar la consistencia y exactitud de los datos. Se define en distintos niveles dependiendo de la parte de la BD afectada.

🏛️

INTEGRIDAD DE ENTIDAD

La tabla requiere que todas sus filas sean únicas. Se garantiza definiendo para cada fila un identificador único (clave primaria). Por ejemplo, en ARTICULO cada fila representa un artículo único — no puede aparecer registrado en dos filas.

🎯

INTEGRIDAD DE DOMINIO

El conjunto de valores aceptables de un atributo es el dominio. La integridad de dominio determina las condiciones que deben cumplir los valores a almacenar en una columna. Se define mediante reglas de validación, valores predeterminados, conjuntos de valores permitidos (FK), tipo y formato. Ej: PrecioProveedor no puede ser negativo.

🔗

INTEGRIDAD REFERENCIAL

Garantiza que la relación entre la clave primaria (tabla referenciada) y la clave foránea (tabla de referencia) siempre se mantiene. Una fila referenciada no puede anularse ni cambiar su valor de PK si hay filas que apuntan a ella. Ej: ARTICULO debe pertenecer a solo una LINEA existente.

🌊 INTEGRIDAD REFERENCIAL EN CASCADA

Cuando se intenta eliminar una fila de una tabla a la que apuntan claves foráneas, la eliminación falla si quedarían filas "huérfanas". La integridad referencial en cascada controla las acciones mediante las cláusulas ON DELETE y ON UPDATE.

NO ACTION
La eliminación/actualización produce un error.
CASCADE
También se eliminan/actualizan todas las filas con claves foráneas que apuntan a la fila afectada.
SET NULL
Las filas con FK que apuntan a la fila eliminada se configuran con NULL en la clave foránea.
SET DEFAULT
Las filas con FK se configuran al valor predeterminado de la columna FK.

Ejemplo: Definir integridad en cascada entre LINEA y ARTICULO — al eliminar una línea, se eliminan automáticamente sus artículos:

T-SQL · CASCADE
-- Eliminar FK existente
ALTER TABLE ARTICULO
DROP CONSTRAINT FK_Articulo_Linea
GO
-- Recrear FK con CASCADE
ALTER TABLE ARTICULO
ADD CONSTRAINT FK_Articulo_Linea
FOREIGN KEY( CodLinea )
REFERENCES LINEA
ON DELETE CASCADE
GO

RESTRICCIONES
(CONSTRAINTS)

Las restricciones son el método preferido para forzar la integridad de los datos. Forman parte de la definición de las tablas y son el método estándar ANSI para garantizar que los datos ingresados sean válidos y que se mantengan las relaciones entre tablas.

🔑
PRIMARY KEY

Garantiza que cada fila sea única. No permite NULL ni duplicados. Se puede aplicar sobre una o varias columnas (clave compuesta).

PK_nombre
🔗
FOREIGN KEY

Define la columna o combinación que relaciona la tabla secundaria con la primaria. Establece la integridad referencial.

FK_tabla_ref
🚫
UNIQUE

Garantiza que cada valor en una columna sea único. A diferencia de PK, permite valores NULL.

U_tabla_col
⚙️
DEFAULT

Establece el valor predeterminado para una columna cuando no se especifica al insertar. Útil cuando la columna es NOT NULL.

DF_tabla_col
✅
CHECK

Establece la regla que debe cumplir un valor para ser aceptable en una columna. Implementa reglas de negocio sencillas.

CK_tabla_col

🔑 SINTAXIS PRIMARY KEY

T-SQL · PRIMARY KEY
-- En tabla existente:
ALTER TABLE TIENDA
ADD CONSTRAINT PK_TIENDA
PRIMARY KEY( CodTienda )
GO
-- Clave primaria compuesta:
ALTER TABLE ORDEN_DETALLE
ADD CONSTRAINT PK_ORDEN_DETALLE
PRIMARY KEY( NumOrden, CodArticulo )
GO

🔗 SINTAXIS FOREIGN KEY

T-SQL · FOREIGN KEY
ALTER TABLE ARTICULO
ADD CONSTRAINT fk_Articulo_Linea
FOREIGN KEY( CodLinea )
REFERENCES LINEA
GO
La columna CodLinea de ARTICULO referencia la PK CodLinea de LINEA. La FK apunta a la clave primaria de la tabla referenciada.

🚫 UNIQUE · ⚙️ DEFAULT · ✅ CHECK

T-SQL · UNIQUE + DEFAULT + CHECK
-- UNIQUE: nombre no duplicado
ALTER TABLE LINEA
ADD CONSTRAINT U_Linea_NomLinea
UNIQUE( NomLinea )
GO
-- DEFAULT: Descontinuado = 0 por defecto
ALTER TABLE ARTICULO
ADD CONSTRAINT DF_Articulo_Descontinuado
DEFAULT 0 FOR Descontinuado
GO
-- CHECK: precio no puede ser negativo
ALTER TABLE ARTICULO
ADD CONSTRAINT CK_Articulo_PrecioProveedor
CHECK( PrecioProveedor >= 0 )
GO
