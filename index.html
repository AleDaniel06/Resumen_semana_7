1. ¿QUÉ ES UNA TABLA?

📋 Definición

Una tabla es un objeto de la base de datos utilizado como almacenamiento de datos. Tiene formato fila-columna similar a las tablas de Microsoft Excel.

📌 FILAS — Registros

Cada fila es un registro único. No existe una fila igual a otra en la misma tabla.

📌 COLUMNAS — Campos

Cada columna almacena valores de propiedades del registro. Debe definirse el tipo de dato antes de crear la tabla.

📌 TIPO DE DATO

Define el tipo de información (cadena, número o fecha) que almacena la columna. Cada columna tiene solo un tipo.

🗂️ Ejemplo: Tabla EMPLEADO

Cada fila = un empleado único. Columnas posibles:

apellido_paterno
cadena
fecha_nacimiento
fecha
estado_civil
cadena
numero_hijos
numérico

⌨️ Sintaxis CREATE TABLE

T-SQL · SINTAXIS BASE
CREATE TABLE nombre_tabla ( nombre_columna1 tipo_dato1 [NULL|NOT NULL] , nombre_columna2 tipo_dato2 [NULL|NOT NULL] , nombre_columna3 tipo_dato3 [NULL|NOT NULL] )
NULL / NOT NULL: establece si el dato es obligatorio (NOT NULL) u opcional (NULL). Si no se especifica, depende de la configuración ANSI null default de la BD.

📊 Ejemplo: Tabla TIENDA

T-SQL · TABLA TIENDA
USE QhatuPERU GO CREATE TABLE TIENDA ( CodTienda int NOT NULL , Direccion varchar(60) NULL , Distrito varchar(20) NULL , Telefono varchar(15) NULL , Fax varchar(15) NULL ) GO

2. TIPOS DE DATOS
EN SQL SERVER 2022

SQL Server organiza sus tipos de datos en 7 categorías. Antes de crear una tabla es fundamental conocerlos para asignar el tipo correcto a cada columna.

2.1 Numéricos Exactos

Permiten especificar exactamente la escala y precisión. Usados en aplicaciones financieras.

Tipo de datoDescripción
bitEntero. Solo puede tomar el valor 1, 0 o NULL.
tinyintEntero de 1 byte. Valores de 0 a 255.
smallintEntero de 2 bytes. De −32,768 a 32,767.
intEntero de 4 bytes. De −2,147,483,648 a 2,147,483,647.
bigintEntero de 8 bytes. De −9,223,372,036,854,775,808 a 9,223,372,036,854,775,807.
decimal(p,s)p = precisión (1–38, default 18). s = escala (0 hasta p). Usado cuando se requiere exactitud.
numeric(p,s)Equivalente a decimal. Mismo rango y comportamiento.
smallmoneyValor monetario 4 bytes. De −214,748.3648 a 214,748.3647.
moneyValor monetario 8 bytes. De −922,337,203,685,477.5808 a 922,337,203,685,477.5807.

2.2 Numéricos Aproximados

Sin precisión exacta. Usados en aplicaciones científicas con grandes decimales.

TipoDescripción
float(n)n=1–24: 4 bytes, 7 dígitos. n=25–53: 8 bytes, 15 dígitos. Default n=53.
real / float(24)Numérico de 4 bytes. Valores de −3.40E+38 a 3.40E+38.

2.3 Fecha y Hora

Puede almacenarse como datetime, smalldatetime o tipos separados.

TipoDescripción
datetime01/01/1753 – 31/12/9999. Intervalo hasta 23:59:59.997. 8 bytes.
smalldatetime01/01/1900 – 06/06/2079. Intervalo hasta 23:59:59. 4 bytes.
dateFecha del 01/01/0001 al 31/12/9999. 3 bytes.
datetime2(p)01/01/0001 – 31/12/9999. Precisión de 100ns. p=0–7 dígitos.
time(p)00:00:00.0000000 a 23:59:59.9999999. p=0–7 dígitos.
datetimeoffset(p)Fecha y hora con reconocimiento de zona horaria.

2.4 Cadenas de Caracteres (No Unicode)

TipoDescripción
char(n)Longitud fija. n = 1–8000 bytes.
varchar(n|max)Longitud variable. n=1–8000. max = hasta 2³¹−1 bytes.
text *Hasta 2³¹−1 caracteres. (*) Usar varchar(max) en su lugar.

2.5 Cadenas Unicode (nchar/nvarchar)

TipoDescripción
nchar(n)Unicode longitud fija. 1–4000 caracteres. Almacenamiento = 2n bytes.
nvarchar(n|max)Unicode longitud variable. 1–4000 caracteres. max = 2³¹−1.
ntext *Unicode variable hasta 2³¹−1. (*) Usar nvarchar(max) en su lugar.

2.6 Cadenas Binarias

TipoDescripción
binary(n)Binario longitud fija. n = 1–8000 bytes.
varbinary(n|max)Binario longitud variable. max = hasta 2³¹−1 bytes.
image *Binario 0 a 2³¹−1 bytes. (*) Usar varbinary(max) en su lugar.

2.7 Tipos Especiales

TipoDescripción

hierarchyidPosición en una jerarquía organizacional.
sql_variantCualquier tipo excepto text, ntext, image, timestamp, sql_variant.

rowversionNúmeros binarios únicos autogenerados dentro de la BD.
uniqueidentifierGUID de 16 bytes. Identificadores únicos en el sistema.

4. MODIFICACIÓN DE TABLAS
— ALTER TABLE

🔧 4.1 Instrucción ALTER TABLE — Sintaxis

T-SQL · ALTER TABLE
ALTER TABLE nombre_tabla ADD nombre_columna propiedades_columna | DROP COLUMN nombre_columna | ALTER COLUMN nombre_columna nuevas_propiedades_columna | ADD CONSTRAINT nombre_restriccion PRIMARY KEY… | UNIQUE… | FOREIGN KEY… | DEFAULT… | CHECK… | DROP CONSTRAINT nombre_restriccion
✦ ADD: crea una nueva columna en la tabla.
✦ DROP COLUMN: elimina una columna existente.
✦ ALTER COLUMN: cambia propiedades de una columna.
✦ ADD CONSTRAINT: añade PK, FK, UNIQUE, DEFAULT o CHECK.
✦ DROP CONSTRAINT: elimina una restricción.

🔍 sp_help — Ver definición de tabla

Procedimiento de sistema que muestra la definición completa de un objeto de la BD (propiedades, columnas, restricciones e índices).

T-SQL · sp_help
-- Sintaxis: sp_help nombre_objeto_basedatos -- Ejemplo: sp_help TIENDA GO

➕ Ejercicio 3.4 — Añadir columna NULL

T-SQL · ADD COLUMN NULL
USE QhatuPERU GO -- Crear tabla de prueba: CREATE TABLE TablaPrueba ( campo1 INT NOT NULL , campo2 CHAR(10) NOT NULL , campo3 DATETIME NULL ) GO -- Añadir columna NULL (siempre funciona): ALTER TABLE TablaPrueba ADD campo4 MONEY NULL GO

➕ Ejercicio 3.5 — Añadir columna NOT NULL a tabla con datos

Pasos necesarios cuando la tabla ya tiene registros:

T-SQL · ADD NOT NULL (3 PASOS)
-- Paso 1: agregar como NULL primero ALTER TABLE TablaPrueba ADD campo6 DECIMAL(12,3) NULL GO -- Paso 2: actualizar valores en filas existentes UPDATE TablaPrueba SET campo6 = 123.456 WHERE campo1 = 1 UPDATE TablaPrueba SET campo6 = 678.123 WHERE campo1 = 2 GO -- Paso 3: redefinir columna como NOT NULL ALTER TABLE TablaPrueba ALTER COLUMN campo6 DECIMAL(12,3) NOT NULL GO
Nota: ALTER TABLE solo permite añadir columnas NOT NULL si la tabla está vacía, si la columna tiene DEFAULT, o si es columna IDENTITY.

5. INTEGRIDAD
DE DATOS

La integridad de datos es el mecanismo para garantizar la consistencia y exactitud de los datos. Se define en distintos niveles según la parte de la BD afectada.

🏛️

5.1 Integridad de Entidad

La tabla requiere que todas sus filas sean únicas. Se garantiza definiendo para cada fila un identificador único (clave primaria).

Ejemplo: en ARTICULO, cada fila representa un artículo único y no puede aparecer registrado en dos filas distintas.

🎯

5.2 Integridad de Dominio

El conjunto de valores aceptables de un atributo es el dominio. Determina las condiciones que deben cumplir los valores de una columna.

Se define mediante: reglas de validación, valores predeterminados, conjunto de valores permitidos (FK), tipo y formato. Ejemplo: PrecioProveedor no puede ser negativo.

🔗

5.3 Integridad Referencial

Garantiza que la relación entre la clave primaria y la clave foránea siempre se mantiene. Una fila referenciada no puede anularse ni cambiar su PK si hay filas que la apuntan.

Ejemplo: cada artículo en ARTICULO debe pertenecer a una línea existente en LINEA.

🔲 Significado del valor NULL

Si una columna tiene la propiedad NULL y no se especifica el valor, el motor almacena el valor NULL. Este valor indica que para dicha fila el valor de esa columna es desconocido o no está disponible. Un valor NULL no es lo mismo que una cadena de longitud cero, ni una cadena de espacios, ni el valor 0.

NOT NULL

El dato es obligatorio. No se puede insertar la fila sin proporcionar ese valor.

NULL

El dato es opcional. Si no se proporciona, el motor almacena NULL (dato desconocido).

6. RESTRICCIONES
(CONSTRAINTS)

Las restricciones son el método preferido para forzar la integridad de los datos. Forman parte de la definición de las tablas y son el estándar ANSI para garantizar que los datos sean válidos y que se mantengan las relaciones.

🔑
PRIMARY KEY

Cada fila única. No NULL ni duplicados. Clave simple o compuesta.

PK_nombre
🔗
FOREIGN KEY

Relaciona la tabla con la PK de otra tabla. Integridad referencial.

FK_tab_ref
🚫
UNIQUE

Cada valor es único. A diferencia de PK, permite valores NULL.

U_tab_col
⚙️
DEFAULT

Valor predeterminado cuando no se especifica al insertar.

DF_tab_col
✅
CHECK

Regla que debe cumplir un valor para ser aceptable en la columna.

CK_tab_col

6.1 PRIMARY KEY — Ejercicio 3.7

Definir CodTienda como clave primaria de la tabla TIENDA ya creada:

T-SQL · PRIMARY KEY
USE QhatuPERU GO ALTER TABLE TIENDA ADD CONSTRAINT PK_TIENDA PRIMARY KEY( CodTienda ) GO -- Verificar: sp_help TIENDA GO

6.2 UNIQUE — Ejercicio 3.13

El nombre de una línea no puede duplicarse. Crear restricción UNIQUE en NomLinea:

T-SQL · UNIQUE
USE QhatuPERU GO ALTER TABLE LINEA ADD CONSTRAINT U_Linea_NomLinea UNIQUE( NomLinea ) GO

6.3 FOREIGN KEY — Ejercicio 3.12

Crear FK en ARTICULO que referencia a LINEA:

T-SQL · FOREIGN KEY
USE QhatuPERU GO ALTER TABLE ARTICULO ADD CONSTRAINT fk_Articulo_Linea FOREIGN KEY( CodLinea ) REFERENCES LINEA GO
CodLinea de ARTICULO referencia la PK de LINEA. Garantiza que cada artículo pertenezca a una línea válida.

6.4 DEFAULT (Ej. 3.14) & CHECK (Ej. 3.15)

T-SQL · DEFAULT + CHECK
-- DEFAULT: Descontinuado = 0 por defecto ALTER TABLE ARTICULO ADD CONSTRAINT DF_Articulo_Descontinuado DEFAULT 0 FOR Descontinuado GO -- CHECK: el precio no puede ser negativo ALTER TABLE ARTICULO ADD CONSTRAINT CK_Articulo_PrecioProveedor CHECK( PrecioProveedor >= 0 ) GO

7. INTEGRIDAD REFERENCIAL
EN CASCADA

Cuando se intenta eliminar una fila de una tabla a la que apuntan claves foráneas, la eliminación falla si quedarían filas "huérfanas". La integridad referencial en cascada controla las acciones mediante las cláusulas ON DELETE y ON UPDATE.

7.1 Opciones de la cláusula ON DELETE / ON UPDATE

NO ACTION (por defecto)

La eliminación o actualización genera un error. La operación no se realiza.

CASCADE

También se eliminan o actualizan todas las filas con claves foráneas que apuntan a la fila afectada.

SET NULL

Las filas con FK que apuntan a la fila eliminada se configuran con NULL en la clave foránea.

SET DEFAULT

Las filas con FK se configuran al valor predeterminado de la columna FK.

8. Eliminación de tablas — DROP TABLE

T-SQL · DROP TABLE
-- Sintaxis: DROP TABLE nombre_tabla -- Eliminar tabla sin FK activas: DROP TABLE ORDEN_DETALLE GO
⚠️ Importante: Si la tabla es referenciada por una FK, primero debe eliminarse la tabla que contiene la clave foránea; luego, la tabla referenciada. De lo contrario SQL Server genera un error.

7.2 Ejercicio 3.16 — Cascada en LINEA → ARTICULO

Al eliminar una línea en LINEA, se eliminan automáticamente todos sus artículos en ARTICULO:

T-SQL · ON DELETE CASCADE
USE QhatuPERU GO -- Verificar estado actual: SELECT * FROM LINEA SELECT * FROM ARTICULO GO -- Paso 1: Eliminar la FK existente ALTER TABLE ARTICULO DROP CONSTRAINT FK_Articulo_Linea GO -- Paso 2: Recrear FK con ON DELETE CASCADE ALTER TABLE ARTICULO ADD CONSTRAINT FK_Articulo_Linea FOREIGN KEY( CodLinea ) REFERENCES LINEA ON DELETE CASCADE GO -- Probar: eliminar la línea 1 DELETE FROM LINEA WHERE CodLinea = 1 GO -- Verificar: los artículos de esa línea desaparecen SELECT * FROM LINEA SELECT * FROM ARTICULO GO
